# 插件（节点）开发指南 · 面向第三方开发者

> 适用版本：FrameWeave 0.3.45（engine_api `1.0`，manifest `schema_version` 2）
> 读者：想给 FrameWeave 写自己节点、不打算改主程序的人。
> 读完你应该能：30 分钟内做出一个能装、能连、能出结果的节点，并打包分享给别人。

---

## 1. 插件是什么

**一个插件 = 一个目录 + `manifest.json` + `node.py`。**

```
user_hello_pack/
├─ manifest.json     # 我是谁：类型名、端口、参数、权限
└─ node.py           # 我怎么干活：一个 Python 类
```

平台负责调度、缓存、进程隔离、权限管控、参数面板渲染；**你只写"输入 → 输出"这一步**。
插件跑在独立子进程里（默认），所以崩溃不会带崩主程序，也拿不到不该拿的东西。

| 平台替你做 | 你要做 |
|---|---|
| 画布渲染端口、校验连线类型 | 声明输入/输出端口 |
| 参数面板、类型转换 | 声明参数与控件类型 |
| 增量缓存（同输入不重跑） | 保证 `run()` 是纯函数 |
| 子进程隔离、超时、杀进程树 | 用 `ctx["run_tracked"]` 起外部命令 |
| 密钥加密存储 | 声明需要哪个密钥，用 `ctx["resolve_secret"]` 取 |

## 2. 五分钟跑通第一个插件

下面这份代码是**实测通过**的：过了全部 manifest 校验、能装上、三种输入场景都能出结果。

### 2.1 建目录

```
user_hello_pack/
├─ manifest.json
└─ node.py
```

> 目录名规则：`<前缀>_<名字>`，**必须与 type_id 对应**——`user/hello_pack` ⇄ `user_hello_pack`。

### 2.2 `manifest.json`

```json
{
  "schema_version": 2,
  "engine_api": "1.0",
  "type_id": "user/hello_pack",
  "title": "示例 · 文案包装",
  "category": "控制",
  "description": "把上游文案加上前缀并统计字数",
  "version": "1.0.0",
  "kind": "python",
  "runtime": "python",
  "entrypoint": "node.py",
  "class_name": "HelloNode",
  "inputs": [
    {"name": "script", "type": "SCRIPT", "label": "文案", "required": false,
     "default": null, "widget": "text", "options": [], "description": "上游文案；留空时用参数直填"}
  ],
  "outputs": [
    {"name": "wrapped", "type": "SCRIPT", "label": "包装后的文案"},
    {"name": "report", "type": "JSON", "label": "统计报告"}
  ],
  "params": [
    {"name": "prefix", "type": "STRING", "label": "前缀", "required": true,
     "default": "【开头】", "widget": "text", "options": []},
    {"name": "direct_text", "type": "STRING", "label": "直填文案", "required": true,
     "default": "", "widget": "text", "options": []},
    {"name": "uppercase", "type": "BOOL", "label": "转大写", "required": true,
     "default": false, "widget": "toggle", "options": []}
  ],
  "permission": {}
}
```

三个**实测踩过的坑**（照抄错误写法一定装不上）：

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 输入端口和输出端口**同名** | 安装失败：`G5: 端口名同时出现在 inputs 与 outputs` | 换个名字（本示例输出叫 `wrapped`） |
| 写了 `"signature": {}` | 安装失败：`G10: signature.key_id 必填` | **第三方直接不写 `signature` 字段** |
| type_id 用了 `core/` 或自造前缀 | 安装失败：`前缀未登记` | 个人插件统一 `user/` 前缀 |

### 2.3 `node.py`

```python
from __future__ import annotations
import json
from typing import Any, Dict

from app.assets import Asset
from app.nodespec import NodeBase, NodeSpec, PortSpec, PortType


def _asset_text(store: Any, asset: Any) -> str:
    """读上游 SCRIPT 资产。

    ⚠️ 必须「文件路径优先、资产 id 兜底」：插件跑在独立进程里，
    同进程新落盘的资产 id 是局部 id，跨节点直接按 id 读会拿到空。
    """
    if asset is None:
        return ""
    p = getattr(asset, "path", "") or ""
    if p:
        try:
            with open(p, "r", encoding="utf-8") as f:
                data = json.load(f)
            if isinstance(data, dict) and isinstance(data.get("text"), str):
                return data["text"]
            if isinstance(data, str):
                return data
        except (OSError, ValueError):
            pass
    aid = getattr(asset, "id", "") or ""
    if aid:
        try:
            data = store.read_json(aid)
        except Exception:
            data = None
        if isinstance(data, dict) and isinstance(data.get("text"), str):
            return data["text"]
    return ""


class HelloNode(NodeBase):
    @classmethod
    def spec(cls) -> NodeSpec:
        # 必须与 manifest.json 逐字一致（端口名、类型、默认值）
        return NodeSpec(
            type_id="user/hello_pack",
            title="示例 · 文案包装",
            category="控制",
            version="1.0.0",
            inputs=[PortSpec(name="script", type=PortType.SCRIPT, label="文案", required=False)],
            outputs=[
                PortSpec(name="wrapped", type=PortType.SCRIPT, label="包装后的文案"),
                PortSpec(name="report", type=PortType.JSON, label="统计报告"),
            ],
            params=[
                PortSpec(name="prefix", type=PortType.STRING, label="前缀",
                         required=True, default="【开头】", widget="text"),
                PortSpec(name="direct_text", type=PortType.STRING, label="直填文案",
                         required=True, default="", widget="text"),
                PortSpec(name="uppercase", type=PortType.BOOL, label="转大写",
                         required=True, default=False, widget="toggle"),
            ],
        )

    async def run(self, ctx, inputs, params) -> dict:
        store = ctx["store"]
        progress = ctx.get("progress") or (lambda p: None)

        body = _asset_text(store, inputs.get("script")).strip()
        if not body:
            body = str(params.get("direct_text") or "").strip()
        if not body:
            raise RuntimeError("invalid: 文案为空——请连接上游文案，或在参数里填「直填文案」")

        text = str(params.get("prefix") or "") + body
        if bool(params.get("uppercase")):
            text = text.upper()
        progress(0.6)

        script_asset = store.save_asset(
            Asset(id="", kind=PortType.SCRIPT.value, meta={"chars": len(text)}),
            payload={"text": text},
        )
        report_asset = store.save_asset(
            Asset(id="", kind=PortType.JSON.value, meta={"chars": len(text)}),
            payload={"chars": len(text), "from_upstream": inputs.get("script") is not None},
        )
        progress(1.0)
        return {"wrapped": script_asset, "report": report_asset}
```

### 2.4 打成 zip

zip 里**只能有一个顶层目录**，目录名 = 包目录名：

```
user_hello_pack.zip
└─ user_hello_pack/
   ├─ manifest.json
   └─ node.py
```

命令行打包：

```bash
# 注意：不要带上 __pycache__
cd 你的工作目录
zip -r user_hello_pack.zip user_hello_pack -x "*/__pycache__/*"
```

### 2.5 安装

**界面**：左侧「插件」面板 → 上传 zip。

**API**（脚本化时）：

```bash
curl -X POST http://127.0.0.1:8788/api/user_nodes/install \
     -H "X-FW-Local-Token: <本地令牌>" \
     -F "file=@user_hello_pack.zip"
# 成功：{"ok":true,"pkg":"user_hello_pack","type_id":"user/hello_pack","version":"1.0.0","state":"active",...}
# 失败：HTTP 200 + {"ok":false,"code":"...","message":"..."}
```

本地令牌在应用数据目录：`<安装数据目录>/local-token`（开发模式为 `dev-local-token`）。

### 2.6 验证

1. 画布双击空白 → 搜「示例 · 文案包装」→ 添加；
2. 参数面板应出现三个控件：前缀（文本）、直填文案（文本）、转大写（开关）；
3. 填一句文案 → 运行 → 连「文案」输出到任意文本节点看结果；或直接看节点详情里的资产。

装成功后 `GET /api/user_nodes` 能看到它；卸载/禁用/回滚都有对应 API（§12）。

## 3. manifest 字段速查

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema_version` | ✅ | 固定 `2` |
| `engine_api` | ✅ | 当前 `"1.0"`；主版本不匹配会拒绝安装 |
| `type_id` | ✅ | `user/<小写名字>` |
| `title` / `category` / `description` | ✅/✅/— | `category` 取值：`输入` `分析` `语义` `音频` `剪辑` `输出` `控制` |
| `version` | ✅ | semver；**改行为必须升级**（缓存按版本失效） |
| `kind` / `runtime` | ✅ | `python` / `python` |
| `entrypoint` / `class_name` | ✅ | `node.py` / 你的类名 |
| `inputs` / `outputs` / `params` | 建议 | 见 §4、§5 |
| `permission` | — | 见 §8；不声明 = 不能读写文件、不能连网、不能起进程 |
| `deps` | — | 模型等外部依赖声明（`{kind:"model", name:...}`），平台据此提示下载 |
| `signature` | 官方包才需要 | 第三方**不要写** |

## 4. 端口：类型决定能连谁

| 类型 | 用途 | 可连到 |
|---|---|---|
| `VIDEO` `AUDIO` `IMAGE` | 媒体资产 | 同类型；`VIDEO→IMAGE` **不允许**（必须插抽帧节点） |
| `SCRIPT` | 长文本（文案/台词） | `SCRIPT`、`JSON`、`ANY` |
| `SEGMENTS` | 分段列表（场景/字幕段） | `SEGMENTS`、`JSON`、`ANY` |
| `SUBTITLE` | 字幕 | `SUBTITLE`、`JSON`、`ANY` |
| `TIMELINE` | 时间线 | 同类型等 |
| `JSON` | 万能结构化 | 几乎全部（含 `SCRIPT/SEGMENTS/SUBTITLE/STRING`） |
| `STRING` `INT` `FLOAT` `BOOL` | 基础值 | 同名、`JSON`、`ANY` |
| `ANY` | 不挑 | 任意 |

命名规则：小写下划线；**同一插件的输入名与输出名不能重复**。

`required: true` + `default: null` + 未连线 → 运行报「必需输入未连接」。
所以：**要么给默认值，要么声明 `required: false` 并在 `run()` 里校验**。

---

## 5. 参数与面板控件

| `widget` | `type` | 面板表现 |
|---|---|---|
| `text` | `STRING` | 单行输入 |
| `number` | `INT` / `FLOAT` | 数字输入 |
| `select` | 任意 | 下拉，候选取 `options` |
| `toggle` | `BOOL` | 开关 |
| `file` | `STRING` | 文件选择（路径） |

约定：

- **默认值必须能直接跑通**（空字符串可以，但不要默认指向不存在的文件）；
- `required: true` 的参数在面板里会高亮缺失；
- 敏感信息不要做成普通 `text` 参数里写明文，用 `@secret:名称`（§7）。

## 6. `run()` 里能用的 `ctx`

| 键 | 用途 | 备注 |
|---|---|---|
| `ctx["store"]` | 资产库：`save_asset` / `read_json` / `get` / `delete` | 见 §6.1 |
| `ctx["progress"]` | `progress(0.0~1.0)` | 长任务务必调用 |
| `ctx["logger"]` | `logger({"level":"info","msg":"..."})` | 写进后端日志 |
| `ctx["run_tracked"]` / `ctx["spawn_tracked"]` | 起外部命令（推荐） | 见 §9 |
| `ctx["resolve_secret"]` | `resolve_secret("名称")` → 明文密钥 | 见 §7 |
| `ctx["http"]` | 受限 HTTP 客户端 | 需 `permission.network` |
| `ctx["fs_read"]` / `ctx["fs_write"]` | 受限文件读写 | 需 `permission.fs` |
| `ctx["workdir"]` | 资产根目录 | 临时文件请放这下面 |
| `ctx["node_id"]` | 当前节点实例 id | 日志用 |

> 不存在 `ctx["cancel_event"]`：长任务靠足够细的 `progress` 与平台的取消（会杀进程树）。
> 不要用 `isinstance(ctx, dict)` 判断——用 `ctx.get("键", 默认值)`。

### 6.1 资产怎么写

```python
from app.assets import Asset

# 结构化数据
asset = store.save_asset(
    Asset(id="", kind="JSON", meta={"chars": 42}),
    payload={"text": "..."},          # 会被存成 JSON
)
# 媒体文件：先写到 ctx["workdir"]，再把 path 交给 Asset
asset = store.save_asset(Asset(id="", kind="VIDEO", path=out_mp4, meta={"fps": 24}))
return {"video": asset}
```

**返回值里的键必须是你 `outputs` 声明过的端口名**，否则平台丢弃且不报错。

## 7. 密钥怎么读

1. 用户在「设置 → 密钥库」里录入，名字例如 `llm_api_key`；
2. 你的参数写 `@secret:llm_api_key`，或直接让用户在参数里填这个名字；
3. 代码里解析：

```python
raw = str(params.get("api_key") or "").strip()
if raw.startswith("@secret:"):
    key = ctx["resolve_secret"](raw[len("@secret:"):])
elif raw:
    key = raw
else:
    raise RuntimeError("contract: 请填写 API Key 或用 @secret:名称 引用密钥库")
```

密钥只存在本机加密库，插件拿到的永远是明文副本，**不要写日志、不要写进产物**。

`permission.secret.refs` 决定你能读哪些名字：`["llm_api_key"]` 精确放行，`["*"]` 全放行
（不推荐，审核会挑）。

## 8. 权限声明

```json
"permission": {
  "fs":         {"read": ["%DATA%/**"], "write": ["%DATA%/mydir/**"]},
  "network":    {"allow": ["api.example.com:443"], "deny": []},
  "subprocess": {"enabled": true, "argv_allowlist": ["ffmpeg", "ffprobe"]},
  "secret":     {"refs": ["llm_api_key"]},
  "env":        {"vars": ["HTTPS_PROXY"]}
}
```

| 你会看到 | 说明 |
|---|---|
| `[fs] 权限拒绝: ...` | 路径不在 `fs.read/write` 白名单里 |
| `[network] 权限拒绝: ...` | 域名/端口不在 `network.allow` |
| `[subprocess] 权限拒绝: ...` | 命令不在 `argv_allowlist`（按 argv[0] 文件名匹配） |
| `[secret] 权限拒绝: ...` | 密钥名不在 `secret.refs` |

**最小权限**：用到什么写什么。什么都不声明 = 只能算数据，不能碰外部世界。

## 9. 起外部命令（ffmpeg / 模型推理 / 其他）

```python
cmd = ["ffmpeg", "-y", "-i", src, "-vf", "scale=1280:-2", dst]
out = await ctx["run_tracked"](cmd, timeout=300)     # 超时会抛 TimeoutError
if out.returncode != 0:
    raise RuntimeError(f"invalid: ffmpeg 失败：{(out.stderr or '')[-400:]}")
```

规矩：

1. **不要用 `subprocess.run/Popen`**：绕过审批、跟踪和进程树清理，取消时杀不掉。
2. **解析 stdout 用 `app.nodespec.stdout_text(out)`**：两种执行模式下 `.stdout` 类型不同
   （`bytes` / `str`），直接 `.decode()` 会在子进程模式下抛异常。
3. 子进程模式下 `.stdout` 只是**末尾 4,000 字符**：要完整输出用
   `ctx.get("run_tracked_full")`（存在时）重跑。
4. **Windows 命令行上限 8,191 字符**：`-filter_complex` 这类会膨胀的参数写成文件再传
   （`-filter_complex_script`），否则会看到莫名的「ffmpeg 退出码 -1」。
5. 命令必须在 `permission.subprocess.argv_allowlist` 里。

## 10. 调试与排错

| 症状 | 原因 | 处理 |
|---|---|---|
| 安装报 `G5: 端口名同时出现在 inputs 与 outputs` | 输入输出重名 | 改名 |
| 安装报 `G10: signature.key_id 必填` | 写了空的 `signature` | 删掉 `signature` 字段 |
| 安装报 `plugin_dir_mismatch` | 更新包的顶层目录名与已安装的不一致 | 保持同一目录名 |
| 安装报 `manifest_type_id` | 目录名与 type_id 不对应 | `user/a_b` ⇄ `user_a_b` |
| 节点显示但参数面板是空的 | manifest 里没写 `params`，或 spec 与 manifest 不一致 | 两边对齐 |
| 运行报「必需输入未连接」 | `required` 且无默认值且没连线 | 连线 / 给默认值 / 改 `required:false` |
| 运行报「文案为空」这类 `invalid:` | 你自己 `raise` 的用户可见错误 | 按提示改输入 |
| 输出端口没有值 | 返回字典的键名与 `outputs` 不一致 | 对齐端口名 |
| 改了代码但结果没变 | 命中缓存 | 提高 `version`，或界面上对该节点「重置并强制重算」 |
| 上游文本读出来是空 | 跨节点按资产 id 直读 | 路径优先（§2.3 的 `_asset_text`） |
| `[subprocess] 权限拒绝` | 没声明 argv 白名单 | 改 `permission` 重装 |

日志位置：

- 应用数据目录 `logs/backend.log`（后端与节点输出）
- 开发模式：后端控制台直接打印

## 11. 版本、升级与回滚

- 改代码 → **升级 `manifest.version`**（缓存与更新判断都靠它）。
- 重新打包 zip（**顶层目录名不变**）→ 再上传，即为覆盖安装，平台自动备份旧版。
- 相关 API：

```bash
GET  /api/user_nodes                       # 列表与状态
POST /api/user_nodes/{pkg}/update          # 上传新包
POST /api/user_nodes/{pkg}/disable|enable  # 停用/启用
POST /api/user_nodes/{pkg}/rollback        # 回滚到上一版
POST /api/user_nodes/{pkg}/uninstall       # 卸载
GET  /api/user_nodes/{pkg}/healthcheck     # 健康检查
```

## 12. 分享与上架

| 目的 | 做法 |
|---|---|
| 给朋友用 | 界面「插件」面板导出，或 `GET /api/export/node/{type_id}` 下载 zip |

## 13. 发布前自检清单

- [ ] `manifest.json` 能被安装（无 G5/G10/前缀错误）
- [ ] `spec()` 的端口/参数与 manifest 完全一致
- [ ] `run()` 是纯函数：同输入同输出（不要塞时间戳/随机数进产物）
- [ ] 所有输出端口都有值，键名 = `outputs` 里的名字
- [ ] 媒体产物有真实 `path`，且文件存在
- [ ] 错误带 `invalid:` / `contract:` 前缀，不是静默返回空
- [ ] 用了外部命令：argv 白名单已声明、stdout 用 `stdout_text` 解析
- [ ] 用了密钥：`@secret:` + `resolve_secret`，日志里没有明文
- [ ] `version` 已升级
- [ ] zip 内只有一个顶层目录，不含 `__pycache__`

## 14. 附：类型速查

| 想表达 | 用端口类型 | 产物形态 |
|---|---|---|
| 一段文案 | `SCRIPT` | `save_asset(Asset(kind="SCRIPT"), payload={"text": "..."})` |
| 结构化数据 | `JSON` | `payload={...}` |
| 视频/音频/图片 | `VIDEO`/`AUDIO`/`IMAGE` | `Asset(path=本地文件)` |
| 分段/字幕条 | `SEGMENTS`/`SUBTITLE` | `payload={"segments":[{start,end,text}]}` |
| 单个数值 | `FLOAT`/`INT` | 直接返回数字（不必 save_asset） |
| 开关结果 | `BOOL` | 直接返回 `True/False` |

> 需要主程序内部契约（校验门编号、槽位推导、缓存键算法）时，看**平台仓**的
