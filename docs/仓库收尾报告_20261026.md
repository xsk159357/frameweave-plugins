## 2. B：`check_signature.py --dist` 归档签名校验

### 2.1 口径（这条最容易错，先钉死）

平台 `backend/app/signatures.py:324-332` 的 `sign_archive_signature()` 是：

```python
"value": sign_bytes(sha256_bytes(zip_path), priv)     # 对 zip 的 sha256 摘要签名
```

即 **签名对象 = zip 整体字节的 sha256 摘要**，不是裸 zip 字节。实测对照（75 个 zip）：

| 口径 | 通过 | 失败 |
|---|---|---|
| A) `sign(sha256(zip))` ← **平台真实口径** | **75** | 0 |
| B) `sign(zip 原始字节)`（"zip 整体字节签名"的字面读法） | 0 | 75 |

所以本仓实现按 A 走；`sdk/README`/报告/脚本注释里都注明这一点，防止下一个人按字面读法写出"全红"的验签器。
`.sig` 文件形态 = 独立 JSON：`{"alg":"ed25519","key_id":"a8998646b062c170","value":"<base64 64B>","over":"archive"}`（与平台 `sign_archive_signature` 返回值一致；平台另有"签名写在 zip 内 manifest"的变体 `extract_archive_signature`，本仓 `dist/` 不用它）。

[sig][dist] archive：校验 75 个 zip → 75 ARCH_SIG_OK / 0 失败
[sig] 允许清单命中 0 条（均为已知未闭合项，不阻断合并）

`NO_SIG` 与 manifest 侧同口径：**永不豁免**（哪怕允许清单里有同名条目——丢签名不是豁免理由）。

### 2.3 默认行为与开关

| 命令 | 行为 |
|---|---|
| `check_signature.py` | **只验 manifest**（与 t9 完全一致，输出里多一个 `[manifest]` 前缀） |
| `check_signature.py --dist` | manifest + dist 归档，两侧分别汇总 |
| `check_signature.py --only-dist` | 只验 dist（`--pkg` 与它互斥，给了就 exit 2） |
| `check_signature.py --json` | 新增 `archive{checked,arch_sig_ok,failed[]}` 段与 `mode{manifest,dist}` |

允许清单作用域（本轮**未新增任何条目**）：条目可用 `"scope": "archive"` + `"zip_sha256"` 豁免归档失败（`manifest` 侧仍只认 `manifest_sha256`，两侧互不串味）。因为 `dist/` 现状 **0 失败**，清单保持 4 条不变。

## 4. C：一键自检入口

### 4.1 两个入口

| 文件 | 形态 | 内容 |
|---|---|---|
| `.githooks/pre-commit` | sh（Git for Windows 用自带 sh 执行） | ① `python sdk/check_all.py --with-workflows --with-signature` ② `python sdk/check_signature.py --only-dist`；失败打印「下一步看哪份文档」并**原样透传退出码** |
| `sdk/precommit.cmd` | cmd（可双击 / 计划任务 / CI） | 同上（`chcp 65001` 保证中文可读；`SKIP_DIST=1` 可跳第二步） |

启用方法（写进 `README.md` §3.1）：

```bash
git config core.hooksPath .githooks      # 启用（仓库级，只影响本机）
git config --unset core.hooksPath        # 关闭
```

### 4.2 为什么 `--dist` 进默认门（取舍）

`dist/` 只有 956 KB / 75 个 zip，归档验签实测 **0.37 s**（`real 0m0.371s`）—— 成本可忽略，而商城产物恰好是最该验的一层，
所以**纳入默认门**；怕吵可 `SKIP_DIST=1 git commit ...` 或单独 `python sdk/check_signature.py --only-dist`。
（对照：若 `dist/` 将来涨到 GB 级，把第二步从 hook 里摘掉、留到发版前跑即可。）

### 4.3 三情况实测（原文见 `.tmp/t12-dist/hook_*.txt` / `cmd_*.txt`）

| 情况 | `.githooks/pre-commit` | `sdk/precommit.cmd` |
|---|---|---|
| ① 全绿 | **exit 0**：`门禁汇总：包=OK / workflows-meta=OK / signature=OK → PASS`；`[sig][dist] 75 ARCH_SIG_OK / 0 失败`；末行 `[pre-commit] PASS` | **exit 0**（同上输出，末行 `[precommit] PASS - all node-repo checks green`） |
| ② 改坏一个 manifest（`core_asr.title` 加后缀） | **exit 1**：`FAIL core_asr SIG_FAIL(ed25519 验签不通过…)` → `[pre-commit] 被拦下（exit 1）—— 下一步看：…` | **exit 1**：`[precommit] BLOCKED (exit 1) - next steps, read:` + 四行文档指针 |
| ③ 锚缺失（`FW_OFFICIAL_PUBKEY=C:/nonexistent/…`） | **exit 2**：`[sig] 环境缺失：官方公钥锚不存在…（缺锚 = 环境缺失，不是通过）` + `exit 2 = 环境缺失… 不是通过` | **exit 2**：同左（英文摘要 + `NOT a pass`） |

接线验证：临时 `git config core.hooksPath .githooks` → `git hook run pre-commit` → exit 0 → **已还原**（`git config --unset`，当前 `core.hooksPath` 未设置）。
三种情况下 `packages/core_asr/manifest.json` 的 sha256 均恢复到基线 `e033fc19…`，`git status -- dist` 恒为 0 条。

### 4.4 踩坑记录：`.cmd` 必须 CRLF（实测）

首版 `sdk/precommit.cmd` 用 LF 行尾 ⇒ `cmd.exe` 把批处理**逐字当命令执行**：

```
'全绿' 不是内部或外部命令，也不是可运行的程序
'（请确认' 不是内部或外部命令…
'flows' …  'commit]' …  'ss' …
```

改成 **CRLF** 后正常。为防止别人 clone 后又被 `core.autocrlf=true` 转坏（hook 被转成 CRLF 会破 shebang、cmd 被转成 LF 会破解析），
新增了**窄范围** `.gitattributes`（不动其他文件既有行为）：

```
.githooks/** text eol=lf
*.cmd      text eol=crlf
```
