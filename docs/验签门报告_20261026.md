## 2. 设计取舍

### 2.1 为什么纯标准库（自实现 ed25519）

节点仓的 SDK 必须在**只有节点仓**的机器上也能跑（双仓契约：私钥与锚归平台仓，节点仓只读锚）。
所以 `check_signature.py`：

- **不 import 平台模块**（不 `sys.path` 到 `FrameWeave/backend`），**不 import 第三方库**；
- ed25519 验签按 **RFC 8032 §5.1.7**（cofactorless：`[S]B == R + [k]A`）用纯 Python 实现（只依赖 `hashlib`），约 60 行；
- 锚只读：默认 `../FrameWeave/backend/app/fw_official_pubkey.json`，可用 `--anchor PATH` 或环境变量 `FW_OFFICIAL_PUBKEY` 指定；
- 自己校验锚的自洽性：`key_id == sha256(公钥原始 32 字节)[:16]`，锚里声明的与派生的不一致 → 直接判环境缺失。

**正确性不是"看起来对"，是与平台实现逐包对拍**：

```bash
$ FrameWeave/backend/.venv/Scripts/python.exe .tmp/t9-sig/crosscheck.py
anchor key_id=a8998646b062c170  pub_len=32
包数 96：本仓实现 SIG_OK=92 / 平台实现 SIG_OK=92 / 判定不一致 0
canonical 字节逐包对拍：不一致 0        # 96 个 manifest 的签名体逐字节相同
```

即：我的纯 Python 实现在 96 个包上与平台 `cryptography` 的判定**完全一致**（含 4 个失败包），
且 `manifest_canonical_bytes()` 的字节与平台**逐包相同** —— 两侧以后仍可互相验签。

### 2.2 canonical 口径（必须与签名侧一致，否则验签全红）

镜像平台 `backend/app/signatures.py` 的 JCS 子集：对象键按 `str(k)` 升序、控制字符 `\u00XX` 转义、
字符串用 `json.dumps(ensure_ascii=False, separators=(",",":"))`、数字走同一套稳定序列化（int 直出 / 整数值浮点去 `.0`），
签名体 = **剥掉 `signature` 键后**的规范化字节。这段实现是**镜像**（不是重新发明），并在文件头注明口径来源。

### 2.3 三态退出码与输出分离

| 退出码 | 含义 |
|---|---|
| **0** | 全部 `SIG_OK`，或失败**全部落在允许清单内** |
| **1** | 存在**未登记失败**（含 `NO_SIG`、`key_id` 不是官方锚、`over` 不是 `manifest`、`alg` 不是 ed25519） |
| **2** | 环境缺失：缺锚 / 锚损坏 / 锚自相矛盾 / 包目录不存在 / `--pkg` 指定的包不存在（**不是通过**） |

单包结果三分类：`SIG_OK` / `SIG_FAIL(<原因>)` / `NO_SIG`（无 `signature` 字段或 manifest 不可解析）。
输出强制把「允许清单命中 N 条」与「未登记失败 M 条」**分行独立**打印，另附「允许清单过期」告警。

另支持 `--json`（机器可读，含 `waived` / `unregistered_failures` / `allowlist_stale`）、`--pkg NAME`（可重复）、
`--packages DIR`（CI 复用）、`--no-allowlist`（严格模式）、`--anchor PATH`。

## 3. 已知例外清单 `sdk/signature_allowlist.json`

4 条，全部是 2026-10-18 构建即失效的 `user_*` 包（t2 已证实工作区内无任何有效签名副本）：

| 包 | version | manifest_sha256（钉住） | since |
|---|---|---|---|
| `user_jsm_highlight_plan` | 1.1.0 | `8a01a3b4…` | 2026-10-18（dist zip 构建即失效） |
| `user_jsm_portrait_matte` | 1.1.0 | `3d2c23ea…` | 同上 |
| `user_jsm_translate_batch` | 1.1.0 | `1c4a8e5e…` | 同上（平台运行目录副本同样验不过） |
| `user_jsm_video_compress` | 1.0.0 | `2536e6e3…` | 同上 |

每条都带 `reason` / `since` / `source_commit`（`144b513` 首次入库带入 10-18 快照）/ `evidence`（指向 t2 的验签证据文件）。
**四条规则**写进清单 `note` 与 `README`：

1. **只减不增**：新增失败不许加进来（加条目 = 改契约，需用户/队长裁定）；删条目同样需用户裁定。
2. **钉 `manifest_sha256`**：登记的包一旦内容变化（哪怕一行），豁免立即失效、门变红 —— 清单不会变成永久的挡箭牌。
3. **只豁免 `SIG_FAIL`**：`NO_SIG`（manifest 丢 `signature`）永不豁免 —— **丢签名不等于豁免**（负向测试 3 实证）。
4. **过期报警**：包恢复有效签名后，门报「允许清单过期」，提示经用户裁定后删除条目。

## 4. 与 `check_all.py` 的关系

`check_all.py` 新增 **`--with-signature`**（与 `--with-workflows` 同风格），另加 `--only-signature`：

```bash
python sdk/check_all.py --with-workflows --with-signature   # 提交前推荐：三门全开
```

**为什么是显式开关而不是默认开启**（任务允许两种，这里选显式，理由如下）：

- 既有调用方（含本仓 README 旧文、历史报告、他人脚本、平台侧文档）都按「只校验包」理解本脚本；
- 验签门需要**平台仓的公钥锚**。在只有节点仓的机器上它必然 exit 2（环境缺失——这是刻意设计的"不是通过"），
  默认开启会让这些环境的 `check_all` 直接变红，属于把环境问题混成代码问题；
- 折中做法：plain 运行会打印一行提示（"加 --with-signature 跑官方锚验签；signed=True 不等于验签通过"），
  README 的「提交前自检」已升级为三门全开，并明确 **改/加节点包必须带 `--with-signature`**。

同时在包门禁的输出里补了一句实话：`（signed=True 仅表示有 signature 对象，验签请开 --with-signature）`，
把原来那条误导性字段的含义钉在输出里。

三门汇总样例（实跑）：

```
[check_all] 校验 96 个包：96 OK / 0 FAILED（signed=True 仅表示有 signature 对象，验签请开 --with-signature）
[wf-meta] 校验 25 个工作流：25 OK / 0 FAILED
[sig] 锚: F:\1223\解说工坊\FrameWeave\backend\app\fw_official_pubkey.json
[sig]       key_id=a8998646b062c170（= 公钥 sha256 前 16 hex，自校验通过）
[sig] 校验 96 个包：92 SIG_OK / 4 失败
[sig] 允许清单命中 4 条（均为已知未闭合项，不阻断合并）
[sig] 未登记失败 0 条
[check_all] 门禁汇总：包=OK / workflows-meta=OK / signature=OK → PASS      # exit 0
```

## 5. 负向测试（证明不是恒绿）

可复现脚本 `.tmp/t9-sig/negative_tests.py`（临时篡改 → 验证 → 恢复 → 自证），最终实跑 **exit 0**：

| # | 动作 | 期望 | 实测 |
|---|---|---|---|
| 1 | 篡改未登记包 `core_asr` 的 `manifest.json`（`title` 加后缀） | exit 1 且指名该包 | **exit 1**，`FAIL core_asr SIG_FAIL(ed25519 验签不通过…)`，91 SIG_OK / 5 失败，未登记失败 1 |
| 2 | 把该包（钉篡改后的 sha）临时加进允许清单 | exit 0 且显示命中允许清单 | **exit 0**，`WAIVED core_asr …`，允许清单命中 5 条 / 未登记失败 0 |

| 4 | 恢复后重跑 | exit 0 / 与基线一致 | **exit 0**；`core_asr/manifest.json` sha256 与 `signature_allowlist.json` sha256 **均与基线相同** |

**B. 商城下架（推荐给不确定还要不要的包）**

从 `packages/` 移除这四个目录 → 删清单条目 → `dist/` 对应 zip 一并下架（`dist/` 属发布链，另开单）。
判决依据可参考：四个包都**不在**出厂种子白名单，下架不影响干净机一条龙。
