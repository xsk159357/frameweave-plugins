> 版本：2026-10-26（对应 0.3.45 现网实现）

> 与 `节点开发规范_20261026.md` 配套：节点讲"单个算子怎么实现"，本文讲"算子怎么连成一条能跑的链"。

## 0. 五分钟读懂

工作流 = **有向无环图**：`nodes`（节点实例 + 参数）+ `edges`（端口到端口的连线）。

```
n1.load_video ──video──► n2.scene_detect ──scenes──► n3.smart_chunk ──chunks──► n4.analyze_chunks
      │                                                                                  │
      └──video──► n7.ai_narrate ◄──descriptions────────────────────────────────────────┘
                        │ narration
                        ▼
                    n9.tts ──marks──► n14.mixed_audio_layout ──layout──► n11.video_render
```

三条铁律：

1. **一条输入端口只接一条入边**。同端口双来源 = 语义由"哪条边后出现"决定，是 2026-10-26 事故的根因
   （见 §3.3 与 §10 已知问题）。
2. **跨名连线必须写 `sourceHandle`**。缺了它只能靠"同名回落 / 类型顺序猜"，猜错就静默读到别的输出端口。
3. **`mode=all` 运行前，每个 `required` 输入必须有入边或 `@asset` 字面量**，否则 422。

## 1. 数据模型

### 1.1 Workflow（平台仓 `FrameWeave/backend/app/engine.py:151`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | 工作流 id |
| `name` | str | 显示名 |
| `nodes` | `{nid: GraphNode}` | 落盘时是数组，`from_dict` 按 id 建索引 |
| `edges` | `[{source,target,sourceHandle,targetHandle}]` | 有向边 |
| `pipeline_stage` / `pipeline_stage_index` | str / int | 影视流水线阶段（断点续跑入口） |
| `pipeline_stages` | list[str] | 阶段定义，默认值可由 `FRAMEWEAVE_PIPELINE_STAGES` 覆盖 |
| `pipeline_checkpoint` | dict | 阶段检查点数据 |
| `created_at` / `updated_at` | float | |

### 1.2 GraphNode（`engine.py:99`）

| 字段 | 说明 |
|---|---|
| `id` / `type_id` | 实例 id / 节点类型（必须已注册） |
| `x` / `y` | 画布坐标 |
| `params` | 参数值（落在节点实例上，不是 spec 默认值） |
| `inputs` | **端口名 → 上游节点 id**（运行期据此找资产） |
| `outputs` | 端口名 → 下游节点 id（展示用，不参与调度） |
| `input_slots` | **端口名 → 上游输出端口索引**（跨名连线的关键，见 §3） |
| `literal_inputs` | 端口名 → 字面量（无连线时直接用，参与缓存键） |
| `status` | `pending/queued/running/success/failed/cancelled/blocked/cached`（对外 `to_dict` 同时给 `status` 与 `state`；`state` 是机器可读终态词汇：`success|cached → succeeded`，其余同名） |
| `asset_ids` | 端口名 → 资产 id（缓存命中的判定依据） |
| `cache_key` / `last_params` / `run_history` | 增量缓存、参数差异高亮、运行历史 |
| `error` / `error_detail` / `progress` | 失败信息与进度 |

> 落盘 JSON 里节点的 `inputs` 在模板里常见为 `{"port": "上游节点id"}`；`input_slots` 可省略，
> 由服务端 `derive_input_slots` 推导（§3.2），也可显式写死（推荐模板显式写）。

## 2. 连线语义

### 2.1 类型兼容

`can_connect(src, dst)`（平台仓 `FrameWeave/backend/app/ports.py`）：

| 源 | 目标 | 允许 |
|---|---|---|
| `ANY` ↔ 任意 | | ✅ |
| 同类型 | 同类型 | ✅ |
| `JSON` | `JSON/SCRIPT/SEGMENTS/SUBTITLE/STRING` | ✅ |
| 任意 | `JSON` | ✅ |
| `VIDEO` | `IMAGE` | ❌（必须显式抽帧） |
| 其他组合 | | ❌（扩展类型默认 deny） |

### 2.2 required 判定

```
必需 = spec.required 且 default is None 且（无入边 且 无 @ 字面量）
```

满足任一即可放行。`@asset:xxx` / `@text:...` 这类字面量写进 `node.inputs[port]` 或
`literal_inputs[port]`，运行前校验认可。

### 2.3 handle 必须存在

边的 `sourceHandle` 必须在源节点 `spec().outputs` 里、`targetHandle` 必须在目标 `spec().inputs` 里。
名字错 → `source_handle_invalid` / `target_handle_invalid`（§4）。

## 3. `input_slots`：跨名连线的落点

### 3.1 为什么需要它

原生画布连线默认"同名对同名"：`n9.tts.marks → n14.narration_items` 是两个不同名端口，
平台必须知道"取上游的**第几个**输出"。`input_slots[n14]["narration_items"] = 2` 就是答案。

### 3.2 推导规则（平台仓 `FrameWeave/backend/app/slots.py: derive_edge_slot`）

按优先级取第一个命中：

1. **`sourceHandle` 精确匹配源节点 outputs** → 用其下标（跨名/同名都正确）
2. 同名回落：`targetHandle` 恰好也是上游的输出名 → 用其下标
3. 类型兼容 + 输出顺序：上游 outputs 里第一个 `can_connect` 到目标输入类型的端口

**2026-10-26 变更**：`derive_input_slots` 由"缺失才写"改为**画布边序后者生效**
（`slots.py` 内注释）。原因：同一输入端口被两条边指向时（估算路 + 实测路），
旧规则把先出现的边固化，后加的、更准确的边被静默丢弃——
实测症状是 `n14` 拿到 `tts.duration`（293.92 这个 float）而不是 `tts.marks`。

### 3.3 双来源 = 事故

```
边 27: n7.narration → n14.narration_items   （脚本估算时长）
边 34: n9.marks    → n14.narration_items    （TTS 实测时长）  ← 后出现者生效
```

这套写法**能跑但语义脆弱**：谁生效取决于边在数组里的顺序与 `inputs` 映射谁最后写入。
规范要求：**不同语义给不同端口名**（如 `narration_items` 与 `narration_marks`），
由节点内部按优先级取值。见 §10 已知问题。

## 4. 图校验与错误码

平台仓 `FrameWeave/backend/app/graph_validator.py`：

| 时机 | 参数 | 行为 |
|---|---|---|
| 保存（create/update） | `check_required=False, skip_unknown_types=True` | 只校验**已知类型之间**的边结构；允许保存引用未安装插件的模板 |
| 运行 `mode=all` | `check_required=True, skip_unknown_types=False` | 未知类型、必需输入、类型不兼容全部硬错误 |
| 运行 `selection/upstream/downstream` | `check_required=False` | 只做结构性校验，避免无关节点未连线阻断局部重跑 |

失败统一 422：

```json
{"ok": false, "code": "graph_invalid", "message": "工作流图校验失败",
 "errors": [{"code": "...", "node_id": "...", "handle": "...", "message": "..."}]}
```

| 错误码 | 触发 | 修法 |
|---|---|---|
| `node_type_unknown` | `type_id` 未注册（包未装/未进出厂集） | 装包；出厂模板要把包进 `BASIC_NODE_DIRS` |
| `edge_invalid` | `edges[i]` 不是对象 | 修数据结构 |
| `source_node_missing` / `target_node_missing` | 边指向不存在的节点 | 删边或补节点 |
| `source_handle_invalid` / `target_handle_invalid` | 端口名写错 | 对齐 `spec().outputs/inputs` |
| `port_type_incompatible` | 类型不兼容 | 插转换节点（如抽帧、JSON 中转） |
| `required_input_missing` | 必需输入无入边/字面量 | 连线，或给参数默认值，或 `@asset` |

## 5. 执行语义

| 项 | 实现 |
|---|---|
| 调度 | 拓扑分批（同层并发），批内失败不阻断其他分支 |
| 目标集合 | `mode=all` / `selection`（`node_ids`）/ `upstream` / `downstream` |
| 入队 | `POST /api/workflows/{id}/run` → `task_queue.enqueue`，返回 `task_id` + `queue_position` |
| 取消 | `POST /api/workflows/{id}/cancel`（排队中 + 运行中一起取消，杀进程树） |
| 单节点重置 | `POST /api/workflows/{id}/nodes/{nid}/reset`，body `{"force": true}`（force 同时失效该节点缓存，返回 `cache_invalidated`） |
| 级联失效 | 上游将重算时，其下游 `SUCCESS/CACHED` 一起置 `PENDING`，避免"上游变了下游还用旧资产" |
| 断点续跑 | `pipeline_stage/_index/_checkpoint` + `POST /api/workflows/{id}/resume` |

状态词汇：`pending → running → succeeded | failed`，命中缓存记 `cached`。
对外同时暴露 `status`（历史契约，8 个取值）与 `state`（`success|cached → succeeded`，自动化消费用）。

## 6. 增量缓存

缓存键（平台仓 `FrameWeave/backend/app/engines.py:371`）：

```
hash( type_id + version + params(sorted) + literal_inputs(sorted)
      + 每个输入端口的上游资产 id（按 input_slots 解析真实输出端口） )
```

命中条件：键存在 **且** 每个记录的 asset id 在资产库中仍可 `get()`。

推论：

1. 改节点逻辑必须 **bump 节点 version**，否则键不变、命中旧结果。
2. `literal_inputs` 参与键——同一节点改字面量不会串味。
3. **成功但空产出会被缓存**：2026-10-26 实测 `ai_narrate` 输出空文案判成功并进缓存，
   下一轮直接复用空结果（看起来"改了没生效"）。排查时先看 `<data>/assets/cache_index.json`。
4. 清缓存三法：`POST .../nodes/{nid}/reset` body `{"force":true}`（单节点）/ 改参数 / 删 `cache_index.json`（全量）。

## 7. 模板

### 7.1 目录与格式

| 项 | 位置 |
|---|---|
| 正本（可改） | 节点仓 `workflows/<tpl_id>/workflow.json`（+ `meta.json`）；平台侧模板由它单向同步生成 |
| 平台构建产物 | 平台仓 `FrameWeave/backend/app/builtin_templates/<tpl_id>.json`（**随包分发，git 跟踪，禁止手改**） |
| 已安装副本 | `<data>/templates/<tpl_id>/workflow.json`（`FRAMEWEAVE_TEMPLATES` 可覆盖根） |
| 索引 | `<data>/templates/templates_index.json` |

模板 JSON（平台仓 `FrameWeave/backend/app/templates.py:1-16`）：

```json
{
  "tpl_id": "jsm_video_narration",
  "name": "视频解说 · 影视解说全链",
  "description": "...",
  "version": "1.0.0",
  "kind": "workflow",
  "tags": ["解说", "全链"],
  "nodes": [{"id": "n1", "type": "core/load_video", "x": 40, "y": 320,
             "params": {...}, "status": "pending", "inputs": {}}],
  "edges": [{"source": "n1", "target": "n2",
             "sourceHandle": "video", "targetHandle": "video"}]
}
```

**文件名不要带 `.workflow` 中缀**：`.gitignore` 的 `*.work*` 会把它静默忽略，
正本又会变成未跟踪文件（`templates.py:63` 有明确注释）。

### 7.2 分发与对齐（FW-DEV-80）

`get_template(tpl_id)` 读取时做三件事：

1. `_normalize_payload` 就地修正已装副本；
2. 若 `builtin_templates/<id>.json` 存在且**边数多于副本** → 以正本覆盖副本，
   `source→builtin`、版本继承正本（旧版 33 边残留副本会被升级到 35 边）；
3. 只对"有出厂正本"的 id 生效，用户自己改的模板不受影响。

### 7.3 从模板建流

```bash
POST /api/workflows/from-template/jsm_video_narration
```

建流后**回读校验**：`GET /api/workflows/{id}` 的节点数/边数应与模板一致（C0 判据）。

### 7.4 出厂模板的三种失败

| 现象 | 原因 |
|---|---|
| 点开模板 → 422 `node_type_unknown` | 模板引用的包没进出厂集（`build_seed.BASIC_NODE_DIRS`） |
| 跑起来某节点 `required_input_missing` | 模板缺边，或该输入只靠参数填而没给默认值 |
| 画布能显示但节点参数为空 | 模板 `params` 没写默认值，且 spec 默认值为 `None` |

## 8. 模板设计硬规则

1. **一条输入端口只一条入边**。需要两个来源就加端口（`xxx_a` / `xxx_b`）或加中转节点。
2. **跨名连线必须显式 `sourceHandle`**，并在模板里显式写 `input_slots`（不依赖推导顺序）。
3. **`required` 输入必须三选一**：有入边 / 参数有默认值 / 提供 `@asset` 字面量。
4. **参数默认值必须能直接跑通**（空 key 可以，但空视频路径不行——首个输入节点可以留空等用户填，
   其余节点不得依赖"用户一定填了"）。
5. **媒体链路走显式转换**：`VIDEO→IMAGE` 必须插抽帧节点，不要指望类型兼容。
6. **模型类节点默认用小模型**（如 `core/asr` 默认 `small`），大模型作为选项并在说明里写体积。
7. **阶段化**：给 `pipeline_stages` 一条从"装配→分析→文案→配音→成片→导出"的顺序，
   便于断点续跑与 UI 展示。
8. **每个模板 `version` 与边数挂钩**：改结构必须 bump，否则已装副本不会升级。
9. **模板里不要写死机器相关路径**；`n1.load_video.params.path` 留空串。
10. **参数里出现的密钥一律 `@secret:名称`**，不要写明文。

## 9. 开发与验收流程

### 9.1 建流三条路

| 方式 | 入口 | 用途 |
|---|---|---|
| 从模板 | `POST /api/workflows/from-template/{tpl_id}` | 出厂/官方模板 |
| 从空白 | `POST /api/workflows` → `PUT /api/workflows/{id}` | 自研 |
| 导入 comfy | `POST /api/workflows/from-comfy` | 迁移 |

`PUT` 的 body 与 `Workflow.to_dict()` 同构；`nodes[].type`（不是 `type_id`）、`edges[]` 四字段。

### 9.2 自检脚本骨架（C0-C4）

```python
# C0 结构：建流后回读，节点/边数与模板一致
wf = get(f"/api/workflows/{wfid}")
assert len(wf["nodes"]) == 17 and len(wf["edges"]) == 35

# C1 契约：未被 422 拦下（类型全解析、required 全满足）
r = post(f"/api/workflows/{wfid}/run", {"mode": "all"})
assert r.status == 200, r.json()          # 422 → 看 errors[]

# C2 产物：等终态，检查每个节点 status/state 与关键资产
# C3/C4 业务判据：按项目定义（如布局 stats 字段、互斥区间为 0）
```

`mode=all` 返回 200 只代表**入队成功**；必须轮询 `GET /api/jobs` 或工作流快照直到全终态。
轮询期间用 `data-boot`/`progress` 观测，别用固定 sleep。

### 9.3 验收要留的证据

- 工作流 id + 建流后回读的节点/边数
- 运行 `task_id` + 队列位置 + 每个节点终态与错误原文
- 关键产物路径 + `sha256` + `ffprobe` 实测（时长/帧数/分辨率）
- 日志真实路径（`%APPDATA%\FrameWeave\logs\backend.log`、隔离实例日志）
- 观察窗口（开始/结束时间）

### 已知问题（待修，已在本文档登记）

**n14 的 `narration_items` 被两条边指向**（边 27 `n7.narration` 与边 34 `n9.marks`）。
当前靠"边序后者生效"得到正确答案（取 TTS 实测时长），但：

- 模板里 `nodes[].inputs` 仍写着 `narration_items: n7`，与 `input_slots` 指向 n9 的第 2 个输出不一致；
- 任何重排边顺序的编辑器操作都会静默改变语义。

**修法（建议下一轮做）**：`core/mixed_audio_layout` 增加输入端口 `narration_marks`（SEGMENTS），
模板改为 `n7.narration → narration_items` + `n9.marks → narration_marks`，节点内"marks 优先、items 兜底"。
边数不变（仍 35），语义不再依赖顺序。

## 11. 问题 → 定位表

| 症状 | 先看 | 结论 |
|---|---|---|
| 建流 422 `node_type_unknown` | 包是否安装 / 是否进出厂集 | 出厂模板引用的包必须在 `BASIC_NODE_DIRS` |
| 运行 422 `required_input_missing` | `node.inputs` 与 spec.required | 补边 / 给默认值 / `@asset` |
| 运行 422 `port_type_incompatible` | 两端 `spec` 类型 | 插转换节点 |
| 某节点拿到的值"类型对但内容不对"（如 float 当列表） | `node.input_slots` 与该端口入边 | 槽位错位 → 显式写 `input_slots` |
| 改了上游参数，下游没重算 | `cache_key` / `cache_index.json` | 下游仍在缓存 → 级联失效只在"上游将重算"时触发 |
| 全链都 `cached` 但产物是空的 | 上一轮成功但空产出 | 清 `cache_index.json` 或单节点 reset(force) |
| 界面显示 `cached` 而节点从未执行 | 缓存命中 | 正常行为，改参数或清缓存 |
| 模板装了但还是旧的边数 | `builtin_templates` 正本 vs 副本 | FW-DEV-80 只对"正本边数更多"时升级；改结构要 bump version |
