## 0. 五分钟读懂

一个节点 = **一个 Python 类 + 一份 manifest.json**，平台负责调度、缓存、权限、进程隔离。

```
输入端口（上游 Asset）─┐
                      ├─→ run(ctx, inputs, params) ─→ 输出端口（新 Asset）
节点参数（用户填的）  ─┘
```

四条必须同时成立的契约：

| # | 契约 | 违反后果 |
|---|---|---|
| 1 | `manifest.json` 的 `type_id / inputs / outputs / params` 与 `node.py` 的 `spec()` **逐字一致** | 画布能连、运行报 `required_input_missing` / 返回值被丢弃 |
| 2 | `run()` 是**纯函数**：同 `params` + 同上游资产 → 同输出 | 增量缓存命中旧结果（改了代码不生效） |
| 3 | 媒体产物必须 `store.save_asset()` 落盘并返回 `Asset` | 下游读不到、缓存键失效、导出缺文件 |
| 4 | 越界行为（写文件/连网/起进程/读密钥）必须在 `permission` 里声明 | 被 `PermissionGate` 拒绝，节点失败 |

最小可跑包只有三个文件：

```
frameweave-plugins/packages/core_hello/
├─ manifest.json
└─ node.py
```

## 1. 目录、命名与双仓同步

### 1.1 目录形态

```
frameweave-plugins/packages/<目录名>/
├─ manifest.json      # 必需：G1-G10 校验入口
├─ node.py            # 必需：entrypoint 指向它
├─ ui/                # 可选：G8 声明的前端扩展（entry 必须在 ui/ 子树内）
└─ assets/            # 可选：随包静态资源（模板、提示词、小样）
```

`<目录名>` 约定为 `<ns>_<name>`，与 `type_id` 的 `<ns>/<name>` 一一对应：

| type_id | 目录名 | 说明 |
|---|---|---|
| `core/tts` | `core_tts` | 官方包（必须官方签名） |
| `core/analyze_chunks` | `core_analyze_chunks` | 下划线化 |
| `user/jsm_match_visual` | `user_jsm_match_visual` | 社区/自研包 |

> 目录名不是随便起的：平台仓 `FrameWeave/backend/packaging/build_seed.py` 的 `BASIC_NODE_DIRS` 用目录名做出厂清单，
> 改名等于改出厂集合。

### 1.2 双仓分工（硬性，2026-10-26 起）

| 仓 | 路径 | 地位 |
|---|---|---|
| **节点仓** `frameweave-plugins` | `frameweave-plugins/packages/<pkg>/` | **唯一源码正本**，有 git 历史；改节点只改这里 |
| 平台仓 `FrameWeave` | `FrameWeave/backend/user_nodes/<pkg>/` | **运行时缓存**，被 `FrameWeave/.gitignore:27` 整目录忽略；可随时从本仓重建；**禁止手改**，改它不算交付 |
| 平台仓 `FrameWeave` | `FrameWeave/backend/app/builtin_templates/<id>.json` | 工作流**构建产物**，由 `FrameWeave/scripts/sync-builtin-templates.py --write` 从本仓 `workflows/` 单向生成；同样禁止手改 |

顺序是**先正本、后平台**，反过来就是越界：

```bash
# 1) 改正本：frameweave-plugins/packages/<pkg>/（manifest.json / node.py）
# 2) 节点仓门禁：逐包 G1-G10 + workflows meta（必须 exit 0）
FrameWeave/backend/.venv/Scripts/python.exe frameweave-plugins/sdk/check_all.py --with-workflows
# 3) 官方包要重签：须发布私钥且与官方锚 key_id 匹配，无授权不得自行重签（§9 / 工作区双仓规则 §6）
# 4) 平台侧刷新运行时缓存：重新播种（build_seed.py）或按需重装该包，不要手工 cp 覆盖
# 5) 平台侧分离守卫：断言缓存与正本逐文件 sha256 一致（必须 exit 0）
FrameWeave/backend/.venv/Scripts/python.exe FrameWeave/scripts/check-repo-separation.py
```

「改了缓存没改正本」在本项目已经真实发生过：`core_draft_export` 的平台运行副本丢了 G3 花字轨与
G10 遮盖原字幕实现，而 `node.py` 与 manifest 仍在声明这两个能力 ⇒ 运行时静默空转、不报错。
分离守卫的断言 (c)（缓存逐文件 sha256 比对正本）就是为这条设的。

平台侧另有一条回归测试盯着「缓存 = 打包生成树」：平台仓
`FrameWeave/backend/tests/test_ai_label_call_site.py::test_packaging_copy_matches_user_nodes`，
断言 `user_nodes` 与打包生成树逐字节相同——播种没跟上会在构建前测试闸门当场失败。

## 2. manifest v2 字段总表

`schema_version: 2` + `engine_api` 是入口，其余字段按 G1-G10 校验（见 §3）。

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `schema_version` | ✅ | 必须 `2` | v1 走兼容通道（不推荐） |
| `engine_api` | ✅ | `主.次`，如 `"1.0"`；主版本须与平台一致 | 平台当前 `ENGINE_API=1.0` |
| `min_engine_api` / `max_engine_api` | — | 同上格式 | 收窄兼容区间 |
| `type_id` | ✅ | `^([a-z0-9]{2,16})/[a-z0-9][a-z0-9_.-]*$` | 前缀 `core` 仅官方签名包可用 |
| `title` | ✅ | 非空 | 画布/面板显示名 |
| `category` | ✅ | 见 §2.1 | 决定面板分组 |
| `description` | — | 字符串 | 一行说明，写清"做什么、边界是什么" |
| `version` | ✅ | semver | **改行为必须 bump**（缓存键含版本） |
| `kind` | ✅ | `python` \| `transform` | 本文只讲 `python` |
| `runtime` | ✅ | `python` | |
| `entrypoint` | ✅ | 相对路径且必须存在于包内 | 通常 `node.py` |
| `class_name` | ✅ | 包内可导入的类名 | 必须继承 `NodeBase` |
| `inputs` / `outputs` / `params` | 建议 | PortSpec 数组 | python 包缺失按 `[]` 处理，但**缺了就是死节点** |
| `permission` | — | 五作用域，未知键拒绝 | 见 §8 |
| `deps` | — | `model` / `pip` / `bundle` / `market` | 模型类依赖写这里，A9 按需下载读它 |
| `signature` | 官方包 ✅ | `{alg, key_id, value, over}` | `core/` 前缀强制；社区包可空 |

### 2.1 `category` 取值

`输入` / `分析` / `语义` / `音频` / `剪辑` / `输出` / `控制`

面板按此分组排序；写别的值不会报错，但会掉进"其他"。

### 2.2 最小完整示例

```json
{
  "schema_version": 2,
  "engine_api": "1.0",
  "type_id": "user/hello",
  "title": "示例节点",
  "category": "控制",
  "description": "把输入文案加上前缀后输出",
  "version": "1.0.0",
  "kind": "python",
  "runtime": "python",
  "entrypoint": "node.py",
  "class_name": "HelloNode",
  "inputs": [
    {"name": "text", "type": "SCRIPT", "label": "文案", "required": false, "default": null}
  ],
  "outputs": [
    {"name": "text", "type": "SCRIPT", "label": "结果"}
  ],
  "params": [
    {"name": "prefix", "type": "STRING", "label": "前缀", "required": true, "default": "【】", "widget": "text"}
  ],
  "permission": {},
  "signature": {}
}
```

## 3. G1-G10 校验门

校验器：平台仓 `FrameWeave/backend/app/plugin/manifest_v2.py`（`validate_manifest`），
扫描（`declarative.scan`）、安装（`install_zip`）、出厂种子（`build_seed.py`）**同一套门**。

| 门 | 校验内容 | 典型失败 | 怎么修 |
|---|---|---|---|
| **G1** | JSON 可解析、`schema_version`、`engine_api` 必填且格式合法 | `G1: engine_api 必填` | 补 `"engine_api": "1.0"` |
| **G2** | `type_id` 格式 + 前缀白名单；`core/` 必须有签名占位 | `G2: type_id 不合法` / `前缀未登记` | 自研用 `user/`；官方改 manifest 前缀与目录同步 |
| **G3** | `version` semver；`engine_api` 与 `min/max_engine_api` 与平台兼容 | `G3: 平台 1.0 低于 min_engine_api 2.0` | 放宽区间或对齐平台 |
| **G4** | `kind` 白名单、`runtime`、`entrypoint` 存在、`class_name` 合法 | `entrypoint 不存在` | 改路径或补文件 |
| **G5** | 端口声明结构、PortSpec 合法（类型已注册、widget 合法、重名拒绝、媒体端口禁入 params） | `G5: ...` | 见 §4 |
| **G6** | `transform` 的 op 白名单（递归）+ 键 ⊆ outputs | 仅 `kind=transform` 相关 | python 包不涉及 |
| **G7** | `permission` 五作用域、未知键拒绝 | `G7: 未知权限作用域` | 只写 fs/network/subprocess/secret/env |
| **G8** | `dependencies` 的 `channel ∈ {pip,bundle,market}`；`ui.entry` 必须在 `ui/` 子树内 | `ui.entry 逃逸包目录` | 移入 `ui/` |
| **G9** | 大小/成员数/压缩比上限 | 打包过大 | 拆包；模型走 `deps.model` 而非塞进包 |
| **G10** | 签名结构：无签名=社区级+警告；结构非法=拒绝；`core/` 强制签名 | `G10: ...` | 重签（§9） |

安装链路的信任分级（`declarative.install_zip`）：官方锚验签通过 → **L0**；有签名无锚 → L2 并警告；
无签名 → L2。引擎侧 `trust_level()` 对未登记的 `user/` 前缀**fail-closed 判 L2**。

## 4. `spec()` 与端口声明

### 4.1 两类声明必须一致

| 位置 | 作用 | 不一致的后果 |
|---|---|---|
| `manifest.json` 的 inputs/outputs/params | 画布渲染、连线校验、参数面板、G 门 | 面板缺参数 / 连线被拒 |
| `node.py` 的 `spec()` | 注册中心索引、`get_spec()`、缓存键、端口查找 | 运行时读不到端口，返回值被丢 |

`registry.get_spec()` 以 manifest 为准构建 `NodeSpec`；`spec()` 供节点类自述。
**规范做法：manifest 是唯一真源，`spec()` 抄同一份内容**（现有 40+ 官方包都这么写）。

### 4.2 PortSpec 字段

```python
PortSpec(
    name="script",              # 端口名，小写下划线，全包内唯一
    type=PortType.SCRIPT,       # 见 §4.3
    label="文案",                # 面板显示
    required=False,             # True + default=None + 未连线 → run 期报 required_input_missing
    default=None,               # 参数默认值（端口一般不设）
    widget="text",              # text|number|select|file|toggle
    options=[],                 # widget=select 的候选
    description="...",          # 面板悬浮说明
)
```

参数（`params`）与输入（`inputs`）的差别：
`inputs` 走上游连线；`params` 是用户在面板里填的字面量。**同一个语义不要既做端口又做参数**，
除非明确"二选一"（如 `core/tts` 的 `script` 端口 + `direct_text` 参数，注释里写清优先级）。

### 4.3 端口类型

13 个核心类型（平台仓 `FrameWeave/backend/app/ports.py`）：

`VIDEO` `IMAGE` `AUDIO` `SCRIPT` `SUBTITLE` `SEGMENTS` `TIMELINE` `JSON` `STRING` `INT` `FLOAT` `BOOL` `ANY`

连线裁决 `can_connect(src, dst)`：

| 源 | 目标 | 结果 |
|---|---|---|
| `ANY` | 任意 | ✅ |
| 任意 | `ANY` | ✅ |
| 同类型 | 同类型 | ✅ |
| `JSON` | `JSON/SCRIPT/SEGMENTS/SUBTITLE/STRING` | ✅ |
| 任意 | `JSON` | ✅ |
| `VIDEO` | `IMAGE` | ❌（必须显式抽帧节点） |
| 其他 | 其他 | ❌ |

扩展类型：`register_port_type("MY_TYPE", is_media=False, can_broadcast=False)` 显式注册后 G5 才放行；
**未注册的类型名不会被自动创建，校验直接拒绝**（防拼写漂移）。

### 4.4 `required` 的准确语义

运行期判定（`graph_validator.validate_graph`，`check_required=True`）：

```
必需输入 = required 且 default 为 None 且（未连线 且 没有 @asset/@xxx 字面量）
```

满足任一即可：① 有上游连线；② 节点 `inputs[name]` 以 `@` 开头（`@asset:...` 引用）；
③ 参数有非 None 默认值。**只靠"参数里填了路径"不算**——除非该参数就是端口默认值。

## 5. `run()` 契约

```python
from app.assets import Asset
from app.nodespec import NodeBase, NodeSpec, PortSpec, PortType

class HelloNode(NodeBase):
    @classmethod
    def spec(cls) -> NodeSpec: ...

    async def run(self, ctx, inputs, params) -> dict:
        text_asset = inputs.get("text")
        prefix = str(params.get("prefix") or "")
        body = ""
        if text_asset is not None:
            body = str(ctx["store"].read_json(text_asset.id).get("text") or "")
        out = ctx["store"].save_asset(
            Asset(id="", kind=PortType.SCRIPT.value, meta={"chars": len(body)}),
            payload={"text": prefix + body},
        )
        return {"text": out}
```

### 5.1 入参

| 参数 | 形态 | 规则 |
|---|---|---|
| `inputs` | `{端口名: Asset | 基础值}` | **未连线的端口可能整键缺失**，一律 `.get()`；媒体端口是 `Asset`，`SCRIPT/JSON` 可能是 `Asset` 也可能是已解码值 |
| `params` | `{参数名: 值}`（已合并默认值） | 值类型以 manifest 的 `type` 为准；字符串里可能含 `@secret:名称`，必须经 `ctx.resolve_secret` 解析后再用 |

### 5.2 返回值

- 字典键必须 ⊆ `spec().outputs` 的端口名，否则平台丢弃且不报错。
- 媒体端口返回 `Asset`（必带 `path`）；文本/结构化端口返回 `Asset`（`payload=` 存 JSON）或可直接 JSON 序列化的值。
- **数组/长文本一律走 `save_asset`**：下游按 asset id 取，缓存键也依赖 asset id。

### 5.3 错误约定

抛异常即节点失败，平台按前缀分类展示：

| 前缀 | 语义 | 例子 |
|---|---|---|
| `invalid:` | 用户输入/参数不合法，改参数可恢复 | `raise RuntimeError("invalid: 需要 prompt / messages 至少一项输入")` |
| `contract:` | 参数与端口契约冲突（缺密钥、类型不符） | `raise RuntimeError("contract: 请填写 API Key 或用 @secret:名称 引用保险箱")` |
| `[binary_missing]` 等编码错误 | 用 `deps.coded_message` 生成，前端给修复引导 | `deps.coded_message("binary_missing", "ffmpeg", hint)` |

**禁止** `except Exception: return {}` —— 这是历史上"用户侧静默退化"的头号来源
（worker 与主进程行为差异被吞掉，见 `nodespec.stdout_text` 的注释）。

## 6. `ctx` 能力清单（两执行模式差异）

平台有两种节点执行模式：`FW_PLUGIN_EXEC=worker`（默认，子进程 + JobObject）与 `inprocess`（调试）。

| ctx 键 | inprocess | worker | 说明 |
|---|---|---|---|
| `workdir` | ✅ | ✅ | 资产根目录 |
| `store` | ✅ | ✅ | 资产库代理，见 §7 |
| `logger` | ✅ | ✅ | `logger({"level":"info","msg":...})` |
| `progress` | ✅ | ✅ | 0.0–1.0 |
| `node_id` | ✅ | ✅ | |
| `local_token` | ✅ | ✅ | 本地 API 令牌（调 `/api/*` 时用） |
| `resolve_secret` | ✅ | ✅ | 走宿主保险箱（DPAPI），worker 内不直读 |
| `http` | ✅ | ✅ | 受限网络出口（过 `permission.network`） |
| `fs_read` / `fs_write` | ✅ | ✅ | 受限文件访问（过 `permission.fs`） |
| `run_tracked` / `spawn_tracked` | ✅ | ✅ | 托管子进程，见 §8 |
| `track_subprocess` / `untrack_subprocess` | ✅ | ✅ | 手动登记的进程（取消时被杀） |
| `subprocess_registry` | ✅ | ✅ | 进程登记表 |
| `run_tracked_full` | ❌ | ✅ | 拿**完整** stdout；主进程用 `ctx.get("run_tracked_full")` 判空后回落 |
| `cancel_event` / `cache_dir` | ❌ | ❌ | **当前不提供**，节点不要依赖；长任务靠 `progress` + 平台取消（杀进程树） |

跨模式写法：

```python
rt_full = ctx.get("run_tracked_full")
out = await (rt_full or ctx["run_tracked"])(cmd, timeout=120)
text = stdout_text(out)          # 必须用它，见 §8.1
```

## 7. Asset 与资产库

`Asset(id, kind, path, meta, fingerprint, node_id, created_at, size)`。

| 方法 | 语义 | 注意 |
|---|---|---|
| `store.save_asset(asset, payload=...)` | 落盘并返回带 id/path 的 Asset | `payload` 给结构化数据；媒体文件放 `asset.path` |
| `store.get(aid)` | 取元数据 | 找不到返回 `None` |
| `store.read_json(aid)` | 取 JSON 载荷 | 见下方红线 |
| `store.delete(aid)` | 删除 | 谨慎：可能被其他工作流引用 |

### 7.1 红线：跨节点读资产必须 path 优先

worker 模式下节点新落盘的资产，`id` 是**本进程局部 id**（`out:aN`，2026-10-26 引入），
跨进程/跨节点直调时按 id 查不到。正确写法：

```python
def _read_payload(store, asset):
    p = getattr(asset, "path", "") or ""
    if p and os.path.isfile(p):
        with open(p, "r", encoding="utf-8") as f:
            return json.load(f)
    aid = getattr(asset, "id", "") or ""
    return store.read_json(aid) if aid else None
```

代码库里有 40+ 处 `store.read_json(x.id)` 直调点已被这个坑打穿过（`ai_narrate → llm_call`、
`match_visual ← script`）。新节点直接用 `_read_payload` 形态。

### 7.2 kind 与端口类型的映射

`asset.kind` 用 PortType 的字符串值；媒体类（VIDEO/AUDIO/IMAGE/TIMELINE）必须有 `path` 且文件存在，
否则下游 `probe` / 渲染会失败。

## 8. 子进程：必须走托管通道

### 8.1 三条铁律

1. **禁止 `subprocess.run/Popen`**：绕过审批、跟踪与 JobObject，取消时杀不掉，Windows 下还会漏掉
   子进程树。统一用 `ctx["run_tracked"]` / `ctx["spawn_tracked"]`。
2. **解析 stdout 必须用 `stdout_text(out)`**：inprocess 返回 `bytes`，worker 返回 `str`，
   直接 `.decode()` 在 worker 下抛 `AttributeError`。
3. **worker 的 stdout 是诊断尾巴（默认 4,000 字符）**：要解析结构化输出，先看
   `getattr(out, "truncated", False)`，必要时用 `run_tracked_full` 重跑。

### 8.2 argv 白名单

`permission.subprocess.argv_allowlist` 按 **argv[0] 的文件名**匹配（如 `ffmpeg`、`python.exe`）。
不在白名单 → `PermissionDenied`，节点表现为 `[subprocess] 权限拒绝: ...`。

### 8.3 Windows 命令行长度

CreateProcess 上限 8,191 字符。`-filter_complex` 这类可膨胀参数写文件：

```python
if len(expr) > 6000:
    fc = os.path.join(workdir, "filter_complex.txt")
    open(fc, "w", encoding="utf-8").write(expr)
    cmd += ["-filter_complex_script", fc]
else:
    cmd += ["-filter_complex", expr]
```

（2026-10-26 实测：31 段渲染 → `WinError 206` → `spawn` 返回 `-1`，症状是"ffmpeg 退出码 -1"而已。）

## 9. 权限模型

`permission` 五作用域（`worker/perm.py`）：

| 作用域 | 键 | 语义 | 被拒症状 |
|---|---|---|---|
| `fs` | `read` / `write`（前缀数组） | 文件读写白名单 | `[fs] 权限拒绝` |
| `network` | `allow` / `deny`（`host:port` 或 `*`） | 网络出口 | `[network] 权限拒绝` |
| `subprocess` | `enabled` / `argv_allowlist` | 起子进程 | `[subprocess] 权限拒绝` |
| `secret` | `refs` | 可读的密钥名（`*` 全放行） | `[secret] 权限拒绝` |
| `env` | `vars` | 允许透传给子进程的环境变量 | 子进程拿不到变量 |

最小权限写法（真实节点参考 `core_tts`）：只开实际用到的 argv、只放行实际域名、`secret.refs`
显式列名而不是 `*`。

### 9.1 密钥读取

```python
key = ctx["resolve_secret"]("llm_api_key")     # 走宿主保险箱
```

参数里写 `@secret:llm_api_key` 时，节点要自己把 `@secret:` 前缀拆掉再调（或直接校验后传入）：

```python
if raw.startswith("@secret:"):
    key = ctx["resolve_secret"](raw[len("@secret:"):])
```

`WorkerContext` 满足鸭子类型（有 `.get()`），**不要用 `isinstance(ctx, dict)` 判断**——
这是 `core/analyze_chunks` 曾经在主进程正常、worker 里直接拿不到密钥的原因。

## 10. 缓存与幂等

缓存键（`engines.py:371`）由四部分拼成：

```
cache_key = hash( type_id + version + params(sorted json) + literal_inputs(sorted json)
                  + 每个输入端口的上游资产 id（input_slots 槽位感知） )
```

命中条件：键存在 **且** 记录的每个 asset id 在库里都还在（`cache_hit`）。

推论（决定了节点怎么写）：

1. **`version` 是缓存失效开关**：改行为必须 bump，否则老结果继续被复用。
2. **时间戳 / 随机数 / 网络数据不能"隐形"**：要么进 `params`，要么写进 `asset.meta`；
   否则用户以为重跑过，实际拿到旧产物。
3. **成功但空产出也会被缓存**：2026-10-26 实测 `ai_narrate` 返回空文案被判成功 → 缓存 →
   后续轮次直接复用空结果、看起来"改了代码没生效"。改逻辑后按需
   `rm <data>/assets/cache_index.json`（或改任意参数）强制重算。
4. 失败节点不写缓存索引，但**占位产出**（如"分块分析失败：画面不可用"）会被当成功产出缓存。

## 12. 已踩坑清单（2026-10-26 源码全链实测）

| 症状 | 根因 | 正确做法 |
|---|---|---|
| `KeyError: 节点类型未注册: core/llm_call` | worker 子进程 env 白名单没透传 `FRAMEWEAVE_USER_NODES`，`pkg_dir` 解析到真实安装目录 | 平台侧已修；节点侧不要自己算包路径，用 `app.declarative` / `registry` |
| `read_json("")` 返回 `None`，输入凭空消失 | 跨节点直调读上游输出，worker 内新资产 id 为空 | path 优先（§7.1） |
| HTTP 401 / 400 `model_unavailable` | 参数里硬编码了某个网关的模型名/base_url | 空值走全局 `settings.llm`，非空才覆盖（`analyze_chunks` 1.0.2+ 的做法） |
| `ffmpeg 退出码 -1` | 命令行超 8,191 字符，`spawn` 抛 `WinError 206` 被压成 -1 | `-filter_complex_script`（§8.3） |
| 视觉分析全是"画面不可用" | 用的模型不支持图像输入 / 网关无该模型 | 模型能力要在 `deps` 或参数说明里写清；失败要报 `invalid:` 而不是静默占位 |
| 子进程解析在 worker 里 AttributeError | `.stdout` 是 `str` 不是 `bytes` | `stdout_text()`（§8.1） |
| 改了代码但结果没变 | 缓存命中旧产出（version 未 bump / 空产出被缓存） | bump version 或清 `cache_index.json` |
| 中文路径传参被打坏 | PowerShell → 原生 exe 走控制台代码页 | 构建/工具链改用 node/python 拉起；或只传相对 ASCII 路径 |
